## Стратегия и выполнение тестов

Оптимальная стратегия — это гибридный подход к выполнению тестов, который балансирует быструю обратную связь с ограничениями по ресурсам (особенно с лимитом бесплатных минут в GitHub Actions).

### Среды выполнения тестов

| Критерий          | Локальная машина                    | Hosted Runner в GitHub Actions      |
| :---------------- | :---------------------------------- | :---------------------------------- |
| **Стоимость**     | Нулевая (кроме оборудования)        | Бесплатно до 2000 мин/мес, далее платно |
| **Время выполнения**| Не ограничено                       | Ограничено (6 часов на задачу)      |
| **Согласованность**| Низкая ("на моей машине работает")  | Высокая (чистая среда при каждом запуске) |
| **Отладка**       | Простая (интеграция с IDE)          | Сложная (через логи)                |
| **Цикл обратной связи**| Очень быстрый                     | Быстрый, но с задержкой на очередь и запуск |

### Рекомендуемое распределение тестов

| Тип теста                  | Рекомендуемая основная среда | Частота запуска                 |
| :------------------------- | :--------------------------- | :------------------------------ |
| **Юнит-тесты**             | GitHub Actions               | При каждом коммите/PR           |
| **Интеграционные тесты**   | GitHub Actions               | При каждом коммите/PR           |
| **API-тесты (Smoke)**      | GitHub Actions               | При каждом коммите/PR           |
| **UI-тесты (Smoke)**       | GitHub Actions               | При каждом коммите/PR           |
| **Тесты производительности (k6)** | GitHub Actions        | При каждом коммите/PR           |
| **Сканирование безопасности (ZAP)** | GitHub Actions      | При каждом коммите/PR           |
| **UI-тесты (Полная регрессия)** | Локальная машина         | Перед важными слияниями, по расписанию |

### Запуск тестов локально

Вы можете запускать различные наборы тестов локально, используя фильтры. Убедитесь, что веб-приложение запущено в отдельном терминале (`dotnet run --project SocksShoppingStore`).

*   **Запустить быстрые тесты (аналогично CI на ветке `dev`):**
    ```shell
    dotnet test --filter "TestCategory=Unit|TestCategory=Integration|TestCategory=API-Smoke|TestCategory=UI-Smoke"
    ```
*   **Запустить полный набор UI-регрессионных тестов:**
    ```shell
    dotnet test --filter "TestCategory=UI-Regression"
    ```
*   **Запустить все тесты (аналогично CI в Pull Request):**
    ```shell
    dotnet test
    ```
*   **Запустить тесты определенной категории:**
    ```shell
    dotnet test --filter "TestCategory=Unit"
    ```
*   **Собрать покрытие кода (для быстрых тестов):**
    ```shell
    dotnet test --filter "TestCategory=Unit|TestCategory=Integration" --collect:"XPlat Code Coverage" --settings coverlet.runsettings
    ```

# Дорожная карта расширения функциональности

Данный раздел описывает поэтапный подход к развитию приложения. Выбор функций основан на анализе современных практик электронной коммерции и адаптирован для реализации с минимальными затратами ресурсов, при этом предоставляя богатые и разнообразные сценарии для тестирования. Каждая новая функция целенаправленно вводится не для коммерческой ценности, а для тех возможностей тестирования, которые она открывает, что напрямую соответствует основной цели проекта.

## Фаза 1: Фундаментальный пользовательский опыт и персистентность данных

**Цель:** Перейти от анонимного пользовательского опыта к состоянию, где данные пользователя сохраняются и генерируется пользовательский контент.

**Предлагаемые функции:**

*   **Учетные записи пользователей (Регистрация и Вход):** Реализация базовой системы аутентификации. Это является необходимым условием для всех последующих функций персонализации.
    *   *Возможности для тестирования:* Проверка рабочих процессов аутентификации, управление сессиями, тестирование политик паролей, валидация ввода (SQL-инъекции, XSS), обработка ошибок при неверных учетных данных.
*   **История заказов:** Предоставление авторизованным пользователям возможности просматривать свои прошлые заказы.
    *   *Возможности для тестирования:* Тестирование извлечения и отображения данных для аутентифицированных пользователей, проверка целостности данных, тестирование контроля доступа (пользователь А не может видеть заказы пользователя Б).
*   **Отзывы и рейтинги продуктов:** Возможность для пользователей оставлять текстовые отзывы и ставить оценки (звезды) товарам.
    *   *Возможности для тестирования:* Тестирование отправки форм, валидация пользовательского контента, тестирование на уязвимости XSS, взаимодействие с базой данных (JSON-файлом), обновление UI после отправки.
*   **Список желаний (Wishlist):** Позволяет пользователям сохранять товары для будущих покупок.
    *   *Возможности для тестирования:* Управление состоянием, персистентность данных между сессиями, UI/UX для добавления/удаления элементов.

## Фаза 2: Расширенный поиск товаров и вовлечение

**Цель:** Улучшить способы, которыми пользователи находят товары и взаимодействуют с ними, внедряя более сложную логику.

**Предлагаемые функции:**

*   **Фасетный поиск и фильтрация:** Реализация серверной фильтрации по атрибутам, таким как цвет, размер и ценовой диапазон.
    *   *Возможности для тестирования:* Комплексное тестирование API/запросов, нагрузочное тестирование "базы данных" на JSON-файлах, управление состоянием UI, валидация логики комбинаций фильтров.
*   **Система промокодов:** Простая система для применения кодов на скидку в корзине.
    *   *Возможности для тестирования:* Валидация бизнес-логики (правильность скидки, срок действия, лимиты использования), пересчет итоговой суммы в корзине, обработка ошибок для недействительных кодов, негативное тестирование (применение использованного кода).
*   **Базовые AI-рекомендации (Mock):** Вместо тяжелой ML-модели реализовать простую, основанную на логике систему рекомендаций, например, "С этим товаром также покупают...", основанную на статических правилах или простом анализе данных.
    *   *Возможно-сти для тестирования:* Валидация логики рекомендаций, API-тестирование эндпоинта рекомендаций, проверка отсутствия деградации производительности на страницах товаров.

## Фаза 3: Оптимизация транзакций и пост-продажного обслуживания

**Цель:** Построить более полный и реалистичный сквозной процесс покупки.

**Предлагаемые функции:**

*   **Гостевое оформление заказа (Guest Checkout):** Позволяет пользователям совершать покупки без создания учетной записи.
    *   *Возможности для тестирования:* Тестирование параллельных пользовательских потоков (гость vs. зарегистрированный пользователь), обработка временной пользовательской информации.
*   **Интеграция с Mock-платежным шлюзом:** Симуляция взаимодействия с платежным провайдером (например, Stripe или PayPal), обрабатывая успешные, неудачные и ожидающие состояния.
    *   *Возможности для тестирования:* Сквозное тестирование транзакционного потока, обработка ошибок и восстановление, управление состоянием заказов, тестирование с использованием моков API.
*   **Автоматическое подтверждение заказа (Mock):** Симуляция отправки email-подтверждения заказа после успешной покупки.
    *   *Возможности для тестирования:* Тестирование пост-транзакционных триггеров, интеграция с mock-сервисом электронной почты, валидация контента в сообщении-подтверждении.

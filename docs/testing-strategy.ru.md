# Общий план тестирования для "SocksShoppingStore"

Этот раздел представляет собой исчерпывающий перечень тестовых сценариев для расширенного приложения, основанный на лучших практиках тестирования в электронной коммерции.

## Стратегия и покрытие тестами

*   **Уровни тестирования:**
    *   **Модульные (Unit) тесты (NUnit):** Фокус на отдельных методах в контроллерах, сервисах и моделях.
    *   **Интеграционные тесты (NUnit):** Тестирование взаимодействия между компонентами, особенно взаимодействия репозитория с файлом `products.json`.
    *   **API-тесты:** Прямое тестирование RESTful API на корректность, производительность и безопасность.
    *   **Сквозные (End-to-End, UI) тесты (Selenium):** Симуляция полных пользовательских сценариев через веб-интерфейс.
*   **Цели по покрытию:** Высокое покрытие кода (>80%) для модульных/интеграционных тестов. Для UI/API-тестов фокус на покрытии требований, гарантируя, что каждая пользовательская история и функция протестированы.

## Позитивные тестовые сценарии ("Happy Path")

*   **Управление учетной записью:**
    *   Проверить успешную регистрацию пользователя с валидными данными.
    *   Проверить успешный вход с корректными учетными данными.
    *   Проверить, что пользователь может успешно выйти из системы.
*   **Поиск товаров:**
    *   Проверить, что страница каталога загружается и корректно отображает товары.
    *   Проверить, что поиск по валидному названию товара возвращает релевантные результаты.
    *   Проверить, что фильтрация по категории/цене работает ожидаемо.
*   **Корзина покупок:**
    *   Проверить, что пользователь может добавить товар в корзину со страницы каталога и страницы товара.
    *   Проверить, что пользователь может увеличить/уменьшить количество товара в корзине.
    *   Проверить, что пользователь может удалить товар из корзины.
    *   Проверить, что итоговая сумма в корзине корректно обновляется после изменений.
*   **Оформление заказа и оплата:**
    *   Проверить, что зарегистрированный пользователь может завершить процесс оформления заказа.
    *   Проверить, что гостевой пользователь может завершить процесс оформления заказа.
    *   Проверить, что валидный промокод применяет корректную скидку.
    *   Проверить успешную транзакцию через mock-платежный шлюз.
    *   Проверить, что заказ создан и виден в "Истории заказов" после успешной оплаты.

## Негативные и граничные тестовые сценарии ("Unhappy Path")

*   **Управление учетной записью:**
    *   Попытка регистрации с уже существующим email.
    *   Попытка регистрации с невалидным форматом email или слабым паролем.
    *   Попытка входа с неверным паролем/именем пользователя.
*   **Поиск товаров:**
    *   Поиск товара, которого не существует.
    *   Поиск с использованием спецсимволов или строк для SQL-инъекций (например, `' OR 1=1;--`).
    *   Применение конфликтующих или невалидных комбинаций фильтров.
*   **Корзина покупок:**
    *   Попытка добавить в корзину больше единиц товара, чем есть в наличии (требует функционала инвентаризации).
    *   Попытка обновить количество до отрицательного числа или нуля.
*   **Оформление заказа и оплата:**
    *   Попытка применить невалидный или просроченный промокод.
    *   Симуляция неудачного платежа от mock-шлюза и проверка, что заказ не создан.
    *   Попытка оформить заказ с пустой корзиной.
    *   Отправка формы адреса доставки с отсутствующими или невалидными данными.

## Сценарии нефункционального тестирования

*   **Производительность:**
    *   (k6) Измерить время ответа API для ключевых эндпоинтов под симулированной нагрузкой в 10 виртуальных пользователей.
    *   (Browser DevTools) Измерить метрики фронтенда: Page Load Time, LCP и CLS.
*   **Безопасность:**
    *   (OWASP ZAP) Запустить базовое сканирование для проверки на общие уязвимости, такие как отсутствующие заголовки безопасности, XSS и т.д.
    *   Вручную проверить на небезопасные прямые ссылки на объекты (например, попытка доступа к `/orders/123`, не будучи владельцем заказа 123).
*   **Юзабилити и доступность:**
    *   Проверить, что по сайту можно перемещаться, используя только клавиатуру (Tab, Enter, Space).
    *   Проверить, что все изображения имеют описательный alt-текст.
    *   Проверить достаточный цветовой контраст с помощью инструментов браузера.
*   **Совместимость:**
    *   Протестировать ключевые пользовательские сценарии на последних версиях Chrome, Firefox и Edge в десктопном окружении.
    *   Использовать эмуляцию браузера для тестирования адаптивного дизайна на популярных мобильных разрешениях (например, iPhone 12, Samsung Galaxy S21).
